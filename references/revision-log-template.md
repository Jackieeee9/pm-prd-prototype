# 修订记录模板

> 放在文档修订记录表**顶部**，新版本在上。五要素：版本号、日期、作者、逐条变更、是否涉及原型。

## 变更内容写法

用有序列表，一条一小节，**与需求编号一一对应**，动词开头，写结果不写过程：

```html
<ol>
  <li>质检工作台：时间维度新增"自定义"，日期跨度含首尾不得超过1个月，超出即校验拦截；KPI、列表与导出范围随区间生效；</li>
  <li>通话/视频/微信/短信列表：已复检任务新增"复议"按钮，支持修改复议结果、违规类型分类、复检说明与案例标记，提交后覆盖原复检结论并留痕；</li>
  <li>AI质检接口：兴业视频人工播报送检新增"资方"传参，按资方差异化判定（仅后端逻辑，不涉及原型）；</li>
</ol>
```

## 规则

1. **不合并条目**：7 项需求就写 7 条，方便逐条验收和回溯。
2. **不写"优化若干问题"**：无法验收的描述不要写。
3. **标明范围**：纯后端逻辑的条目追加"（仅后端逻辑，不涉及原型）"。
4. **版本号**：需求/原型变更升次版本号（V2.22 → V2.23）；纯文案、纯配置不升版本号，用"轻量变更记录"另起一行。
5. **历史不篡改**：旧版本记录里的旧术语保持原样，但在当次记录中写明更名关系，便于检索对齐。
6. **日期**：使用实际交付日期，不用计划日期。
